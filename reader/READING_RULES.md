# スキャン本 iPhone 読書アプリ共通ルール

更新: 2026-11-09  
対象: 「世界の歴史1」「図説 英国のインテリア史」を含むすべてのスキャン本読書アプリ。

## 1. 画面に収まらない本文・図版説明は次の読書ページに送る（必須）

- 本文、図版の説明・キャプション、囲み記事が端末の**表示可能領域に入りきらない場合**、画面下で文章を途切れさせたり、切り捨てたり、隠したりしない。
- **上スワイプ**（または「次へ」）で同じ文章の続きを**次の読書画面**に表示する。**下スワイプ**（または「前へ」）で前の画面に戻れる。
- 最終行から続きの先頭まで**脱字・重複・勝手な追加文・不自然な段落断絶**を作らない。改ページ位置は画面幅・高さ・選択文字サイズに基づき再計測する。
- 図版・画像は原本のまま一度提示し、その直後に説明文を表示する。画像と説明文の対応付けを保ちつつ、説明が長ければ**説明の途中から続きの読書画面を追加**する。続きで原本画像を無用に複製せず、必要なら「図版説明の続き」と区別できるようにする。
- **読みやすい文字サイズを勝手に小さくして詰め込むことは禁止**。『世界の歴史1』で使う本文20px・列間1.50を基準にし、既存のA−／A＋調整を引き続き有効にする。図版説明は図版表示に適した既存の文字組を尊重する。
- 文字数で強制的に区切らず（26文字固定など不可）、原文の文順・句読点・段落の区別を保持する。

## 2. 原本1枚と読書画面は別の概念

- 各表示内容がどの**原本スキャン画像**に由来するか、その番号・参照・画像ファイルを保持する。原本画像の画素や図版を改変しない。
- 過去の「原本1枚＝読書1ページ（例: 20枚固定）」という整理は**原本との対応**を示すものであり、表示文字数が増える場合でも1画面に全内容を押し込む制限とはしない。
- 画面に収まらなければ**同じ原本から複数の読書ページを作る**。原本スキャン総数は変えず、読書ページ総数は表示幅・文字サイズに応じて増減してよい。
- 原本ページや分冊をまたぐ文章も自然につなぎ、元の原本ページ情報は内部に保持する。

## 3. スワイプ操作とページ番号

- 画面上の次・前の読書ページへの移動を、上下スワイプと「次へ」「前へ」ボタンの両方で利用できるようにする。
- ページ切替で途中の文字が見えなくなる、同じ文章が重複する、続きが次の原本へ飛んでしまう状態を禁止する。
- 「読書ページ 〇 / △」と「原本 〇 / N」は混同しない。読書ページの総数は実際の組版に従って計算する。

## 4. OCR・図版の既存共通方針（継続）

- 日本語縦書きの列順は右から左。OCR由来の不自然な改行を除去し、文章は自然に接続する。
- 部・章・節・小見出し・本文、柱、ページ番号、キャプション、囲み記事、図中の文字を適切に区別する。
- 図や写真、地図、グラフを勝手に分割・再描画せず、原本画像をそのまま保持する。
- 根拠のない文の創作や推測校正をせず、確定した誤字だけ直す。

## 5. 検査が済んで初めて「対応済み」とする

- 画面幅320 / 390 / 430px、文字サイズ16〜30px（2px刻み）などで、画像と長い説明文を含む表示を検証する。
- 特に**図版説明の最後が次の読書ページに続くか**、戻れるか、欠落・重複がないかをテストする。
- GitHubにこのルールを記録しただけでは、既存の読書HTML・Google Drive内の本への**実装済みとはみなさない**。元の読書データの修正、表示・操作テスト、実機確認を区別して記録する。
