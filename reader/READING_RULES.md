# スキャン本 iPhone 読書アプリ共通ルール

更新: 2026-11-09（現行60項目正本に合わせて整合）  
対象: 「世界の歴史1」「世界の歴史2」「図説 英国のインテリア史」を含むスキャン本読書アプリ。

**最優先・唯一の品質検査正本**: Googleドライブの `20261109_0544_【現行・全書籍共通】OCR品質検査60項目_重複除去.md`。旧8/40/96/120項目を重ねて適用しない。本ファイルは画面実装上の補助メモであり別の検査リストではない。異なる場合は05:44版の60項目正本が優先する。

## 1. 画面に収まらない本文・図版説明は次の読書ページに送る（必須）

- 本文、図版の説明・キャプション、囲み記事が端末の**表示可能領域に入りきらない場合**、画面下で文章を途切れさせたり、切り捨てたり、隠したりしない。
- **上スワイプ**（または「次へ」）で同じ文章の続きを**次の読書画面**に表示する。**下スワイプ**（または「前へ」）で前の画面に戻れる。
- 最終行から続きの先頭まで**脱字・重複・勝手な追加文・不自然な段落断絶**を作らない。改ページ位置は画面幅・高さ・選択文字サイズに基づき再計測する。
- 図は原本JPEG/PNGの画素を変えず、図説と同じ読書画面に表示する。説明が長く次ページに続く場合も**同じ図を続きの読書ページに再掲**し、途中で画像を省略しない。図説の文字は分割後に連結して原文と完全一致を確認する。極小画面では図を縮小し、それでも本文が進まない場合だけ図の参照を明示した説明専用ページを使う。空ページ・無限ループは禁止。
- **読みやすい文字サイズを勝手に小さくして詰め込むことは禁止**。『世界の歴史1』で使う本文20px・列間1.50を基準にし、既存のA−／A＋調整を引き続き有効にする。図版説明は明朝体、本文20px時16.8px、line-height 1.48を基準とする。目次は原本の全項目を照合し、文字サイズ22/14/13/12pxを基準とする。
- 文字数で強制的に区切らず（26文字固定など不可）、原文の文順・句読点・段落の区別を保持する。

## 2. 原本1枚と読書画面は別の概念

- 各表示内容がどの**原本スキャン画像**に由来するか、その番号・参照・画像ファイルを保持する。原本画像の画素や図版を改変しない。
- 過去の「原本1枚＝読書1ページ（例: 20枚固定）」という整理は**原本との対応**を示すものであり、表示文字数が増える場合でも1画面に全内容を押し込む制限とはしない。
- 画面に収まらなければ**同じ原本から複数の読書ページを作る**。原本スキャン総数は変えず、読書ページ総数は表示幅・文字サイズに応じて増減してよい。
- 原本ページや分冊をまたぐ文章も自然につなぎ、元の原本ページ情報は内部に保持する。

## 3. スワイプ操作とページ番号

- 画面上の次・前の読書ページへの移動を、上下スワイプと「次へ」「前へ」ボタンの両方で利用できるようにする。
- ページ切替で途中の文字が見えなくなる、同じ文章が重複する、続きが次の原本へ飛んでしまう状態を禁止する。
- 「読書ページ 〇 / △」と「原本 〇 / N」は混同しない。読書ページの総数は実際の組版に従って計算する。

## 4. OCR・図版の既存共通方針（継続）

- **原本が縦書きなら**右列から左列、**原本が横書きなら**原本の段組順・回り込みに従う。英国のインテリア史の横書き原本と読書画面の縦書き表示を混同しない。OCR由来の不自然な改行を除去し、文章は自然に接続する。
- 部・章・節・小見出し・本文、柱、ページ番号、キャプション、囲み記事、図中の文字を適切に区別する。
- 図や写真、地図、グラフを勝手に分割・再描画せず、原本画像をそのまま保持する。
- 根拠のない文の創作や推測校正をせず、確定した誤字だけ直す。

## 5. 表示領域を実測する改ページの安全条件（2026-11-09追記）

- 改ページ判定用の隠し要素と実際の読書画面は、**本文領域の幅・高さ・内側余白・文字サイズ・行間が同じ**でなければならない。CSSの `width:100%` が絶対配置の左右余白を無効化していないか確認する。
- ブラウザーのアドレスバー、上下の操作バー、ホームインジケーター、`safe-area-inset` を除いた**実際に読める高さ**を測る。端末画面全体の高さをそのまま本文の高さに使わない。
- 図版説明の最終行がフッター直上に接触しないよう、目安として**1行以上（約38px）の安全余白**を確保して再組版する。測定後にフォント等が変わりあふれたときも、最後の文字を `overflow:hidden` で隠さず再組版して次画面に送る。図説の内部スクロールは用いない。
- テストは例えば**390×650px（ブラウザUIを除いた小さい実表示領域）**でも行う。単に390×844pxの全画面で通っても合格扱いしない。測定した隠し要素と本表示の実際の横幅・高さ、最下端の余白を記録する。
- 読書画面に重なる固定ボタンを置かない。操作はヘッダー、フッター、目次等に移し、説明本文を覆わない。

## 6. 検査が済んで初めて「対応済み」とする

- 画面幅320 / 390 / 430px、文字サイズ16〜30px（2px刻み）などで、画像と長い説明文を含む表示を検証する。
- 特に**図版説明の最後が次の読書ページに続くか**、戻れるか、欠落・重複がないかをテストする。
- GitHubにこのルールを記録しただけでは、既存の読書HTML・Google Drive内の本への**実装済みとはみなさない**。元の読書データの修正、表示・操作テスト、実機確認を区別して記録する。
