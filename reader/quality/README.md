# 読書本の制作・検査・配布

唯一の品質正本はGoogle Driveファイル `1CngvhZvJPQsGizwmaVKC_old4Vlvxzn2`。既存の60項目IDを維持する。実行手順は [RELEASE_PROCESS.md](RELEASE_PROCESS.md)、継続作業の入口はリポジトリ直下のAGENTS.md。

## 検査の区別

- `reader-quality-gate.cjs`：台帳・60ID・状態・公開入口の構造検査。成功は **SCHEMA PASS ONLY** であり、OCR本文の正確さや配布許可ではない。
- `reader-artifact-audit.cjs`：実HTMLの原本・順序・本文登録の構造検査。画像ハッシュ一致を文字精度と同一視しない。
- `reader-release-control.cjs`：私有側の原本領域、独立転記、校正差分、数値・境界・実表示と、証拠実体・版の対応を検査する。
- `reader-private-pipeline.cjs`：不変な一次データから校正版を履歴付きで管理し、その校正版からのみ生成する。検査済みの配布計画と、直前確認・保存後再取得を分離する。
- `reader-publish-stage.cjs`：全生成後に公開専用のツリーを作る。新規の未検査資産はソースに残して公開物から除外し、既存公開資産の無根拠な変更は停止する。Pagesはこの検査済みツリーだけをアップロードする。

## 順序

制作側検査 → 新規の私有仮保存 → G8-08再取得一致 → 読書入口公開 → G8-03成功・版確認 → 通常版昇格と対象IDの再取得 → G8-04実機確認。

公開前に公開成功を要求せず、実機未実施を実機成功にも読み替えない。旧版を互換目的で維持することは校正合格ではない。未校正版の確認は明示的な依頼と専用preview入口・新規保存が必要で、通常版を置換しない。

## 限界

公開CIは私有の原本を直接読めない。公開記録は私有検査が出したハッシュと判定を結び付けるもので、署名認証や目視実施の証明ではない。原本を本当に確認し、正直な証拠を残す責任は作業者にある。

管理者の直接編集、手動Drive更新、ChatGPTの直接添付までは技術的に封鎖できない。接続ツール作業もplan・verify-plan・complete-planを毎回使う。一般の書籍本文や原本画像をこの公開リポジトリへ保存しない。
