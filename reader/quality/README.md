# 読書本の制作・検査・配布

制作・検査では、**ChatGPTのライブラリにある「全書籍共通ルール」**を出発点とし、選定した実行版の`active_release.json`と一致するファイル名・SHAの正本1件だけを採用する。「現行正本」という文字や新しい日時だけで複数候補から選ばない。履歴フォルダ内の旧版やコピーは使わない。

現行60項目のID・数・順序、小説と世界の歴史1の二基準、制作10工程・統合4工程は維持する。

二基準の制定は2026年11月16日 06:54（日本時間）。2026年11月17日に現行v2見出し書式の記述を実装値へ整合済み。

現行v2の見出しは両基準とも本文20px時22.4px（1.12倍）・太字700・後余白0.82em・字間0で、色だけ`world_history_1`=`#925341`／`novel`=`#000000`。旧校正案に残る1.08倍などは現行標準値ではなく、テンプレート作成やG7-02の基準へ引用しない。

旧Google Drive版は履歴であり、現行正本ではない。検証コード・台帳・証跡に残る旧Drive版のIDは互換性のための識別子で、現行正本の参照先ではない。公開時点の内容を固定している [画面実装メモ](../READING_RULES.md) に記載された旧Drive版も、現行正本として使わない。

既存の60項目IDを維持する。制作・継続作業は [WORK_RESUME_PROCESS.md](WORK_RESUME_PROCESS.md) とリポジトリ直下のAGENTS.md、配布操作は [RELEASE_PROCESS.md](RELEASE_PROCESS.md) を使う。公開版台帳と私有の現行作業版を混同しない。

## 検査の区別

- `reader-work-resume.cjs`：選定された制作工程台帳と品質manifestを一緒に検証し、現在の原稿から不足作業を選ぶ。Work/Chatの移動で初稿へ戻さない。復帰整合は制作許可・品質合格・配布許可ではない。
- `reader-repair-plan.cjs`：既存証拠を保ちながら実行可能な作業と外部待ちを分ける。`work-catalog.json`は全60IDの作業案であり、正本や評価結果を置き換えない。
- `reader-quality-gate.cjs`：台帳・60ID・状態・公開入口の構造検査。成功は **SCHEMA PASS ONLY** であり、OCR本文の正確さや配布許可ではない。
- `reader-artifact-audit.cjs`：実HTMLの原本・順序・本文登録の構造検査。画像ハッシュ一致を文字精度と同一視しない。
- `reader-release-control.cjs`：私有側の原本領域、独立転記、校正差分、数値・境界・実表示と、証拠実体・版の対応を検査する。
- `reader-private-pipeline.cjs`：不変な一次データから校正版を履歴付きで管理し、その校正版からのみ生成する。検査済みの配布計画と、直前確認・保存後再取得を分離する。
- `reader-publish-stage.cjs`：全生成後に公開専用のツリーを作る。新規の未検査資産はソースに残して公開物から除外し、既存公開資産の無根拠な変更は停止する。Pagesはこの検査済みツリーだけをアップロードする。

## 順序

制作側検査 → 新規の私有仮保存 → G8-08再取得一致 → 読書入口公開 → G8-03成功・版確認 → 通常版昇格と対象IDの再取得 → G8-04実機確認。

公開前に公開成功を要求せず、実機未実施を実機成功にも読み替えない。旧版を互換目的で維持することは校正合格ではない。未校正版の確認は明示的な依頼と専用preview入口・新規保存が必要で、通常版を置換しない。

## 保存済みの範囲原本 ZIP と全体原本を区別する

全体原本の ZIP 内の順番をスキャン番号として扱う既存方式は維持する。
保存済みの範囲原本 ZIP を使う場合だけ、PRIVATE の source snapshot に
`scanMapping.schema: reader-source-scan-map-v1`、`archiveScanRange`、
全画像の実スキャン番号と正確な ZIP entry 名の対応を明示する。
ファイル名から番号を推測したり、対象 HTML の番号を付け直して通したりしない。

新方式は ZIP の全 JPEG/PNG を、境界画像を含めて一対一・連番・ZIP 内順序で
照合する。重複、欠落、余剰、範囲外、名前や順序の不一致、不明な mapping は停止する。
対象範囲の各画像には、HTML から作り直していない既存の独立原本 SHA 台帳を必須とし、
実画像 bytes の全件一致を検査する。ZIP 自体の SHA、実画像数、既知 ID と
実フォルダ一覧の照合も引き続き必要。`init-resolved` は得た対象画像 SHA を
その HTML の埋込画像と再照合する。

報告の `originalImageCount` と ZIP SHA は、今回実際に取得した範囲 ZIP の値である。
その親にある全体 ZIP は別の来歴として記録し、metadata のみ確認できた場合は
`metadata_only`、bytes と SHA は未検証とする。範囲 ZIP が合格しても、
全体 ZIP を取得・読取済みにしたり、全書籍の原本照合に格上げしたりしない。
新方式の報告は `sourceScope: downloaded_archive_only` と
`upstreamArchiveBytesVerified: false` を保持する。
具体的な PRIVATE 入力は [制作工程0](BOOK_CREATION_PROCESS.md#保存済みの範囲原本zipを使う場合) を参照。

## 限界

公開CIは私有の原本を直接読めない。公開記録は私有検査が出したハッシュと判定を結び付けるもので、署名認証や目視実施の証明ではない。原本を本当に確認し、正直な証拠を残す責任は作業者にある。

管理者の直接編集、手動Drive更新、ChatGPTの直接添付までは技術的に封鎖できない。接続ツール作業もplan・verify-plan・complete-planを毎回使う。一般の書籍本文や原本画像をこの公開リポジトリへ保存しない。
