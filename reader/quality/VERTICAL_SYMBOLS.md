# 縦書き記号の組版と検査

全書籍共通ルール G7-02「選択テンプレートの書式再現」の実行手順。小説と『世界の歴史1』型の本文・見出し・目次に適用する。

| 記号 | 縦書きでの扱い |
| --- | --- |
| 単独の半角算用数字 `0`～`9`（例 `第2章`、`1世紀`） | 元の1文字を正立させ、1文字分の縦中横で列頭の字形も枠に収める。全角数字は元の縦組字形を使う。複数桁の数値・年号、英数字の識別子、小数・比・範囲の一部はそれぞれ元の組み方を使う。 |
| 疑問符 `?`、`？` | 縦書き読書版ではどちらも全角の `？`（U+FF1F）を正立させる。例：`本当??` は「本当？？」と組む。 |
| `!！‼⁇⁈⁉`、注記・単位記号（例 `※ % ＆ ℃`） | 元の記号を正立させる。連続した別々の文字は各文字を保つ。 |
| 通貨・数学記号（例 `￥ $ ＋ ＝ × ÷`）、矢印・図形（例 `→ ↑ ▼`） | 記号の意味と指す方向を保つため正立させる。 |
| `「」『』（）、。・`、長音 `ー`、ダッシュ `―`、波線 `〜`、リーダー `…‥` | `vertical-rl` と `text-orientation: mixed` でフォントの縦組字形・位置を使う。長音やダッシュは列の方向に伸び、リーダーの点は縦に並ぶ。 |
| その他の約物・記号、絵文字・異体字・結合記号 | Unicodeの縦書き向きとフォントの縦組機能を使う。異体字セレクター、キーキャップ、絵文字の結合列は一組で扱う。 |

原本・OCR・校正本文の文字コードは保持する。全角化は本文・見出し・目次を縦に組むときに行い、改ページ計測と画面表示に同じ変換を使う。表示中の全角疑問符数が、対応する原稿の半角と全角の疑問符の合計に等しく、縦書き画面に半角疑問符が残った場合は検査で検出する。数字は段落の前後の文字から判定する。改ページの試し組みや表示の一部分が `1660` の末尾の `0` だけになっても、年号の一部として扱う。横書きの図説、操作ボタン、カウンターは元の書式を使う。

## Workでの実行

新しい共通テンプレートは本文を組むたびに自動適用する。既存の v2 系エンジンから分冊を再制作する場合は、次を実行する。運用ZIPの `workflow_guard_v9_2/integration/vertical-symbols/` からも同じコマンドを利用できる。

```sh
node tools/reader-vertical-symbols.cjs apply private-novel-engine.js
```

各分冊と統合版を通常の手順で再生成し、出力HTMLそのものを検査する。外部JS方式では候補HTMLと同じ相対位置に配布するJSを置く。コマンドは指定した全ファイルを順に検査して、ファイルごとの結果をJSONで返す。埋込型の確認版では原本枚数・正立記号数・縦組字形に任せる記号数、原稿の半角数字の文字数も出力する。この文字数には複数桁の各桁も含む。正立対象の個数と向きは、段落をつないだ読書画面と測定画面で検査する。

```sh
node tools/reader-vertical-symbols.cjs check 分冊/*.html 統合確認版.html
```

Workで再開すると、採用済みHTMLを検査し、旧式の読書画面には記号の修正作業を追加する。原本校正など並行できる作業は継続する。新しい共通ルールで最終検査や完成判定に進む際には、登録した読書HTMLを自動で再検査する。

画面幅320・390・430px、文字サイズ16～30pxで表示と改ページを確認する。プレビューの縦書き画面では `ReaderVerticalSymbols.inspect(document.getElementById('text-flow'))` で表示中の実測結果を得る。`uprightDigits` は正立対象の半角数字の個数を示す。`mismatches` があるときは、文字コード、期待した向き、実際のCSS、対象ページを記録する。計測用の `measure-text` にも同じ検査を使える。書式・原本の文字列・見出しの改ページ・左端のはみ出しはそれぞれ確認する。

組版の仕様は [W3C 日本語組版処理の要件](https://www.w3.org/TR/jlreq/)、[CSS Writing Modes](https://www.w3.org/TR/css-writing-modes-3/#text-orientation)、[Unicode Vertical Text Layout](https://www.unicode.org/reports/tr50/) に基づく。
